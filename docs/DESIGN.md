# DESIGN.md

このファイルはスマートフォン向けWebアプリのUIを実装・生成する際に参照する「見た目と振る舞いの唯一の正解」を定義する。

---

## 0. プロダクトの世界観と設計思想

- **プロダクト名**: ホールデータまとめ
- **一言で言うと**: パチスロ店舗のホールデータ（日別稼働・狙い台・解析・カレンダー・島の稼働状況など）を可視化し、来店前の判断や台選びの材料を提供するサイト。
- **主要デバイス**: スマートフォン（縦持ち）を第一とする。ただし解析タブ・取材ハブはPC利用が主要想定のため、これらの画面はPC幅での情報量・視認性を優先したレイアウトを許容する（詳細は4章のナビゲーション参照）。横持ちは簡易対応とする。
- **トンマナ**: 実用的で見やすい／情報が信頼できる／親しみやすい
- **デザイン原則（3〜5個、優先順位が高い順）**:
  1. **片手操作を最優先する** — 主要な操作は画面下部1/3（親指が自然に届く範囲）に配置する。
  2. **情報は一画面一目的** — 1つの画面に主要なアクションは1つまで。複数の判断を同時に求めない。
  3. **待たせない・迷わせない** — ローディングは即座にスケルトン表示、エラーは次にすべき行動を必ず示す。
  4. **装飾より機能** — 影・グラデーション・アニメーションは意味（状態変化・階層）を伝えるためだけに使う。
  5. **利用シーンに応じて情報密度を切り替える** — 店舗内でスマホから素早く確認する画面（日別データ・狙い台作成・島図・カレンダー）は簡潔さを優先し、自宅でPCから腰を据えて見る画面（解析・取材ハブ）は情報量・比較のしやすさを優先してよい。

## 1. カラーパレット（役割ベース）

色は「見た目」ではなく「役割」で管理する。新しいコンポーネントを作るときも、下記の役割トークンの中から選ぶ。ここにない色を新規に使わない。

| トークン名 | HEX（Light） | HEX（Dark） | 役割 |
|---|---|---|---|
| `color-primary` | `#2563EB` | `#5B8DF6` | 主要アクション（送信・確定ボタン、選択中タブ） |
| `color-primary-pressed` | `#1D4ED8` | `#4A76D6` | primaryの押下状態 |
| `color-accent` | `#F59E0B` | `#F5A623` | 強調・通知バッジ・新着マーク。**多用しない（1画面に1箇所まで）** |
| `color-success` | `#16A34A` | `#4ADE80` | 完了・成功メッセージ |
| `color-warning` | `#D97706` | `#FBBF24` | 注意（破壊的操作の前段階など） |
| `color-danger` | `#DC2626` | `#F87171` | 削除・エラー・取り消せない操作 |
| `color-bg` | `#FFFFFF` | `#121212` | 画面の背景 |
| `color-surface` | `#F7F7F8` | `#1E1E1E` | カード・シート・入力欄の背景 |
| `color-border` | `#E5E7EB` | `#2E2E2E` | 区切り線・アウトライン |
| `color-text-primary` | `#111827` | `#F2F2F2` | 本文・見出し |
| `color-text-secondary` | `#6B7280` | `#A0A0A0` | 補足・キャプション・placeholder |
| `color-text-disabled` | `#9CA3AF` | `#5A5A5A` | 非活性要素の文字 |

**やってはいけないこと**
- `color-accent` を背景の全面塗り、区切り線、非活性ボタンには使わない（強調が意味を失うため）。
- `color-danger` は削除・エラー以外の目的（例: 単なる装飾赤ボタン）に使わない。
- コントラスト比はWCAG AAを満たすこと（本文文字は背景に対し4.5:1以上）。

## 2. タイポグラフィ

- **フォントファミリー**: 和文 `"Noto Sans JP"`、欧文 `"Inter"`。両方指定できない環境ではOSデフォルト（`-apple-system, "Hiragino Sans", Roboto, sans-serif`）にフォールバックする。
- **行間**: 本文は `1.6`、見出しは `1.3` を基本とする（日本語は英語より行間を広めに取る）。
- **文字サイズは13px未満を使わない**（可読性・タップ領域確保の観点から）。

| 用途 | サイズ / 行高 | Weight | 使用箇所 |
|---|---|---|---|
| Display | 28px / 36px | 700 | オンボーディング等、画面に1回だけ出る大見出し |
| H1 | 22px / 30px | 700 | 画面タイトル（ヘッダー） |
| H2 | 18px / 26px | 600 | セクション見出し |
| Body | 15px / 24px | 400 | 本文・リスト項目 |
| Body Strong | 15px / 24px | 600 | 強調したい本文（金額・件数など） |
| Caption | 13px / 18px | 400 | 補足説明・タイムスタンプ |
| Button Label | 15px / 20px | 600 | ボタン内の文字 |

## 3. レイアウトとスペーシング

- **基準単位**: `4px` を最小単位とし、`4 / 8 / 12 / 16 / 24 / 32 / 48` のスケールのみを使用する。中間値（例: 10px, 18px）を使わない。
- **画面の左右パディング**: `16px` を標準とする（コンテンツ幅が狭いスマホでは詰まりすぎないように）。
- **セーフエリア対応**: iOSのノッチ・ホームインジケーター、Androidのジェスチャーバーを避けるため、必ず以下を適用する。

```css
padding-bottom: calc(16px + env(safe-area-inset-bottom));
padding-top: env(safe-area-inset-top);
```

  また `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` を設定する。
- **ブレークポイント**: `~375px`(小型スマホ) / `376–767px`(標準スマホ、メイン対象) / `768–1023px`(タブレット、2カラム許容) / `1024px以上`(PC、中央寄せ最大幅960pxのカラム表示)。
  - 解析タブ・取材ハブはPC利用が主要想定のため、1024px以上では最大幅960pxの制約を緩め、必要に応じてグラフとテーブルを横並びにする2カラム構成など、情報量を優先したレイアウトを許容する。
- **親指ゾーン設計**: 頻繁に使う操作（送信・次へ・タブ切替）は画面下部、下から `56px〜200px` の範囲（親指が自然に届く範囲）に配置する。画面上部は「戻る」「タイトル表示」など頻度の低い操作にとどめる。

## 4. コンポーネント

### ボタン
- **Primary**: 背景 `color-primary`、文字白、角丸 `12px`、高さ `48px`（タップ領域確保のため48px未満にしない）、押下時は `color-primary-pressed` に切り替え、影は使わない。
- **Secondary**: 背景透明、`1px solid color-border`、文字 `color-text-primary`。
- **Text Button**: 背景なし、文字色のみで表現。破棄・キャンセル等の低優先アクションに使う。
- 1画面内でPrimaryボタンは基本1つまで。複数の主要アクションを並べない。

### 入力フォーム
- 高さ `48px` 以上、角丸 `8px`、背景 `color-surface`、フォーカス時は枠線を `color-primary` に変更（太さ2px）。
- ラベルは入力欄の上に常時表示（placeholderのみに頼らない。入力中にラベルが消えるとユーザーが迷うため）。
- エラー時は枠線を `color-danger` にし、入力欄直下に赤文字でエラー内容と修正方法を1行で表示する。

### カード / リストアイテム
- 背景 `color-surface`、角丸 `12px`、内側パディング `16px`。
- 影は基本使わない。階層を示す必要がある場合のみ `0 1px 2px rgba(0,0,0,0.06)` を使う（「浮いている」ような強い影は使わない）。

### ナビゲーション

**スマホ幅（〜767px）: ボトムタブ + メニュー**
- 主要ナビゲーションは画面下部の固定タブとする（親指で届く・OSの標準パターンに合わせるため）。
- タブは以下5個で固定する。いずれもスマホでの利用頻度が高い機能を優先配置している。
  1. ホーム
  2. 日別データ
  3. 狙い台作成
  4. 島図
  5. カレンダー
- アイコン＋12px前後の短いラベルを併記する。タブの高さは `56px` + セーフエリア分。選択中タブは `color-primary` + アイコンをfilled表現に。
- **解析・取材ハブ**はPC利用が主要想定のため、上記5タブには含めない。ヘッダー右上のメニューアイコン（`aria-label="その他のメニュー"`）をタップすると、下から**ボトムシート**が開き、そこに解析・取材ハブへのリンクを表示する。

**タブレット・PC幅（768px以上）: 上部固定ナビ or 左サイドナビ**
- ボトムタブに代えて、画面上部の固定ナビゲーション、または左サイドの固定ナビゲーションに切り替える。
- この幅ではホーム・日別データ・狙い台作成・島図・カレンダー・解析・取材ハブの7項目すべてを並べて表示してよい（親指ゾーンの制約が緩むため）。
- 選択中タブの表現（`color-primary` + アイコンfilled）はスマホ幅と同様のルールを適用する。

### モーダル / シート
- スマホでは全画面モーダルではなく、下から出る**ボトムシート**を優先する（片手操作・OSジェスチャーとの一貫性のため）。上記「その他メニュー」もこの形式に従う。
- 閉じる操作は「上から下へのスワイプ」と「明示的な×ボタン」の両方を用意する。

## 5. 状態とインタラクション

- **タップ領域は最小44×44px、推奨48×48px**を下回らない（アイコンだけの見た目が小さくても、実際のタップ可能領域はpaddingで確保する）。
- **hover状態を主要な情報伝達に使わない**（タッチデバイスにhoverは存在しないため）。フィードバックは必ず `active`（押下）状態、またはタップ後のトースト/アニメーションで表現する。
- **トランジション**: `150–200ms`、easingは `ease-out` を基本とする。画面遷移は右からスライドイン、モーダルは下からスライドアップ。
- **ローディング**: 空白のまま待たせない。骨組み（スケルトンUI）を即時表示する。3秒以上かかる処理は進捗や見込み時間を示す。
- **エラー**: エラーメッセージは「何が起きたか」だけでなく「次に何をすればいいか」を必ず添える（例: 「通信エラーが発生しました。再読み込みしてください」＋再試行ボタン）。

---

## 6. アクセシビリティ

- コントラスト比はWCAG AA（本文 4.5:1、大見出し 3:1）以上を確保する。
- すべてのタップ可能要素に `aria-label` または視認可能なテキストラベルを付与する（アイコンのみのボタンも例外なく）。
- 動的なコンテンツ更新（トースト、エラー表示）は `aria-live` で読み上げ対応する。
- ユーザーのOS設定（文字サイズ拡大、ダークモード、モーション削減 `prefers-reduced-motion`）に追従する。

---

## 7. やってはいけないこと（Do's / Don'ts）

- ❌ ホバーエフェクトだけで状態を表現しない（タッチデバイスでは発火しない）。
- ❌ 画面上部にだけ主要な操作ボタンを置かない（親指が届きにくい）。
- ❌ トークンにない色・余白・角丸を新しく作らない。似た値で妥協せず、既存トークンから選ぶ。
- ❌ すべての要素に影をつけて「立体的」に見せない。影は階層を示す必要がある場所だけに絞る。
- ❌ エラーメッセージだけを表示して、次の行動を示さない。
- ❌ 横スクロールを主要な操作導線に使わない（誤操作・見落としの原因になりやすい）。
- ❌ 解析・取材ハブをスマホのボトムタブに含めない（利用頻度・利用デバイスの実態に合わないため）。
- ✅ 迷ったら「情報を減らす」方向で判断する。1画面1目的を優先する。

## 8. AIエージェント向けクイックリファレンス

UIを生成する際は以下を必ず守ること。

- 背景: `color-bg` / カード: `color-surface` / 主要アクション: `color-primary`（角丸12px, 高さ48px）
- 本文文字サイズ: 15px、行間1.6、フォント: Noto Sans JP / Inter
- 余白は `4/8/12/16/24/32/48px` のスケールのみ使用
- スマホ幅のナビゲーションはボトムタブ5個（ホーム / 日別データ / 狙い台作成 / 島図 / カレンダー）＋メニューからのボトムシート（解析 / 取材ハブ）
- タブレット・PC幅（768px以上）は上部固定ナビ or 左サイドナビに切り替え、7項目すべてを表示可
- 解析・取材ハブはPC幅での情報量優先レイアウトを許容（2カラム構成など）
- タップ領域は48px以上、hoverではなくactive状態でフィードバック
- 1画面内のPrimaryボタンは1つまで、accentカラーは1箇所まで

**プロンプト例**: 「@DESIGN.mdのルールに従って、[画面名]画面を実装してください。特にボタン・余白・色トークンは新規に作らず、このファイルの定義のみを使ってください。」
